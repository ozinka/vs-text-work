# Технічний огляд і покращення

## Що перевірено

Огляд охопив маніфест VS Code, правила підсвітки, обробники клавіш і сценарії
автоматичних списків. Найбільша концентрація логіки та крайніх випадків була в
`src/extension.js`, тому зміни спрямовано саме туди.

## Виконані покращення

- Логіку списків винесено до `src/list-utils.js`. Вона більше не дублюється між
  `Enter`, `Tab` і `Shift+Tab`.
- Літерні списки правильно продовжуються після `z.` як `aa.` і для великих літер
  (`AZ.` → `BA.`).
- Римські числа перевіряються за коректною формою, тому випадкові комбінації літер
  не обробляються як римські списки.
- Неоднозначні `i.`, `v.`, `x.`, `c.` тощо визначаються за попереднім пунктом на
  тому самому рівні вкладеності, коли такий контекст є.
- Порожній пункт списку тепер перетворюється на звичайний порожній рядок без
  додаткового штучного рядка.
- Вкладення враховує налаштування VS Code: пробіли або символ табуляції.
- Вставлення нового числового пункту перенумеровує наступні числові пункти того
  самого рівня, не чіпаючи вкладені списки.
- Власні слова зібрано за кольорами, а не за тематичними категоріями.
- Прибрано посилання на неіснуючу групу `#keywords` із файлу підсвітки.
- Додано `npm test` та модульні тести для правил списків.

## Пропозиції для наступних ітерацій

| Пріоритет | Пропозиція | Причина |
| --- | --- | --- |
| Високий | Перевірити списки в Extension Host VS Code, не лише модульними тестами. | Це покриє реальне положення курсора, виділення та взаємодію з командами редактора. |
| Середній | Додати справжні VS Code snippets, якщо саме їх мався на увазі користувацький сценарій. | Наразі є команди автосписків, але немає внеску `snippets` у маніфесті. |
| Середній | Винести авторські слова в налаштування розширення або один дуже простий окремий файл. | Тоді нові слова можна додавати без редагування регулярних виразів. Це потребує окремого рішення про формат і кольори. |
| Низький | Додати команду «перенумерувати список» для вже вставленого або відредагованого блоку. | Автопродовження працює під час введення, але навмисно не переписує існуючий список. |
| Низький | Підтримати кілька курсорів і виділені діапазони. | Поточна поведінка, як і раніше, орієнтована на активний курсор. |

## Межі поточної оптимізації

Пошук попереднього пункту йде вгору по документу лише після натискання `Enter` або
`Shift+Tab`. Це лінійний пошук, але для звичайних текстових нотаток він простіший і
надійніший за складне кешування; оптимізувати його передчасно не потрібно.
