# Контекст проєкту Text Work

## Навіщо існує це розширення

Text Work — це розширення VS Code для звичайних текстових нотаток у файлах `.txt`.
Його мета — не перетворювати текст на код і не створювати нову мову програмування.
Натомість воно робить робочий текст легшим для читання: помічає числа, текст у лапках,
скорочення, посилання, теги, списки й важливі для автора слова різними кольорами.

Це інструмент для особистої та робочої текстової інформації: нотаток, статусів,
команд, списків, фрагментів конфігурації та подібного вільного тексту.

## Головний принцип підтримки

Правила мають залишатися простими й зрозумілими без знання внутрішньої термінології
підсвітки VS Code. У документації та в обговореннях варто говорити так:

- **група правил** — невеликий блок на кшталт `numbers`, `tags` або `colors`;
- **слова для підсвітки** — перелік слів усередині правила;
- **колір** — назва кольорового маркера, який отримує знайдений текст.

Технічні назви на кшталт `scope`, `repository` чи `TextMate grammar` потрібні лише
для орієнтації у файлах. Вони не повинні диктувати спосіб організації авторських
слів або змушувати перейменовувати зрозумілі секції.

## Поточні можливості

Розширення підключає режим `text-work` до `.txt` файлів і містить такі можливості:

- підсвітка чисел, сум і значень на кшталт `25`, `12.5`, `$100`, `20k`;
- підсвітка тексту в одинарних і подвійних лапках;
- підсвітка UUID, email-адрес і HTTP(S)-посилань;
- підсвітка великих абревіатур (`API`, `AWS`) та слів із підкресленням;
- підсвітка тегів на кшталт `@task`, позначок перед двокрапкою та пунктуації;
- кольорові списки: марковані, числові, літерні й римські;
- окремі правила для позитивних/негативних статусів, днів, місяців, кольорів і
  робочих ключових слів (наприклад, `git`, `terraform`, `status`, `prod`);
- усі вручну перелічені слова згруповано за кольором: наприклад, `prod` і
  `done` — зелені, `dev` — жовте, `qa` та `uat` — фіолетові;
- продовження та зміна вкладеності списків клавішами `Enter`, `Tab` і `Shift+Tab`;
- зсув нумерації наступних числових пунктів того самого рівня після вставлення
  нового пункту;
- вставка розділювача з поточними датою і часом: `Alt+Enter` після курсора,
  `Shift+Alt+Enter` перед курсором;
- маскування одного слова перед `@pass`, якщо в системі встановлено шрифт
  `PasswordMask`.

## Де що лежить

| Файл або каталог | Призначення |
| --- | --- |
| `package.json` | Маніфест VS Code: режим `.txt`, команди, клавіші та кольори. |
| `syntaxes/text-work.tmLanguage.json` | Усі правила підсвітки та прості переліки слів. Це головне місце для додавання нових слів. |
| `src/extension.js` | Поведінка списків і вставка розділювача з датою/часом. |
| `language-configuration.json` | Пари дужок і лапок, автозакриття, коментарі. |
| `fonts/` | Шрифти `PasswordMask` для режиму маскування. |
| `.github/workflows/` | Автоматичне пакування та публікація релізів. |
| `text.txt` | Основний комплексний приклад для ручної перевірки всіх можливостей. |
| `test.txt` | Попередній короткий ручний приклад. |

## Як додавати власні ключові слова

Відкрийте `syntaxes/text-work.tmLanguage.json` і знайдіть групу потрібного кольору
в блоці `colorWords`: `greenWords`, `redWords`, `yellowWords` тощо. Додайте
нове слово до відповідного переліку через `|`:

```json
"match": "(?i)\\b(status|git|terraform|myWord)\\b"
```

`(?i)` означає, що регістр неважливий; `\\b` не дозволяє збігатися з частиною
довшого слова. Якщо новій групі потрібен інший колір, скопіюйте коротке правило,
залиште для нього зрозумілу назву і виберіть один з уже наявних кольорових маркерів
(`magenta`, `yellow`, `green`, `red`, `blue`, `violet` тощо).

Порядок груп у верхньому списку `patterns` важливий: ранні правила мають вищий
пріоритет. Тому вузькі або спеціальні випадки (наприклад, пароль, UUID, рядок)
краще залишати перед загальними правилами на кшталт чисел чи пунктуації.

## Поточна картина без припущень

Під час огляду коду зафіксовано такі речі:

- у проєкті **немає зареєстрованих VS Code snippets**. Імовірно, під «сніпетами»
  маються на увазі наявні зручні автодії зі списками та розділювачем. Якщо потрібні
  саме snippets VS Code, це окрема невелика функція, яку слід додати;
- окремого правила для заголовків зараз немає. Найближча наявна поведінка —
  підсвітка позначки на початку рядка перед `:` як `label-brown`;
- авторські слова зібрані в одному блоці `colorWords` за кольором, а не за
  тематичними категоріями.

Ці пункти не змінюють задум проєкту: авторські слова повинні залишатися простим,
видимим списком, який легко поповнювати.
